# Home Visit Booking — Requirements & Development Plan

Status: **Design / Phase 1 (free booking, no payments)**

---

## 1. Goal

Allow **self-registered patients** to find a doctor (via the patient doctor search) and request a **home visit** from the doctor. The booking reuses the existing hospital booking infrastructure (`doctor_availability` slots + `assignments` table) instead of creating parallel tables.

## 2. Core design decisions (agreed)

### 2.1 Slots are reused — the doctor controls the purpose

A slot is the doctor's time. There is **one** slot table (`doctor_availability`) and **one** calendar for the doctor. The doctor decides **at creation time** whether a slot/template serves:

- `hospital` (default) — bookable by hospitals (existing production flow)
- `home_visit` — bookable by patients for home visits

Stored as `slot_type` on both `doctor_availability` and `availability_templates`. Slots auto-generated by the cron inherit the template's `slot_type`.

> No toggle endpoint. Real-time switching is NOT planned; the type is fixed at creation. (Revisit later if needed.)

### 2.2 Assignments are reused for both channels

The existing `assignments` table is the single booking record:

- `source = 'hospital'` (default) → existing hospital flow, unchanged
- `source = 'patient'` → new home-visit flow, no hospital involved (`hospital_id` nullable, `patient_profile_id` references `patient_profiles`)

Same status machine, slot locking, expiry and notifications are shared.

### 2.3 Payment-agnostic MVP (no payments in Phase 1)

- **No payments, no fees** in the first version — bookings are **free requests**.
- Future payment model is undecided (patient → doctor, patient → platform → doctor, or admin-set/doctor-set fees).
- The schema stores `consultation_fee` on the assignment but nothing is populated in Phase 1. No payment logic is added now, so no future direction is blocked.

## 3. Schema changes (in place)

| Table | Change |
|---|---|
| `doctor_availability` | `slot_type` text default `'hospital'`, CHECK (`hospital`/`home_visit`) |
| `availability_templates` | `slot_type` text default `'hospital'`, CHECK (`hospital`/`home_visit`) |
| `assignments` | `source` text default `'hospital'`, CHECK (`hospital`/`patient`) |
| `assignments` | `patient_profile_id` uuid FK → `patient_profiles` (ON DELETE SET NULL) |

## 4. Development plan (one piece at a time)

### Phase 1 — Free booking (current)

1. **Schema** — apply the migration. ✅ schema + Drizzle written.
2. **Doctor creates availability with slot type**
   - Repo: `slot_type` accepted on create (template + availability), default `'hospital'`.
   - Service: validate `slot_type`.
   - Cron: generated slots inherit template `slot_type`.
   - Dashboard UI: "Hospital / Home visit" selector in template + Add Slot modals.
   - Prod safety: all existing hospitals/templates keep working — `slot_type` optional, defaults to `hospital`.
3. **Patient booking request (no payment)**
   - `GET /api/bookings/time-slots?type=home_visit&doctorId&date` → available home-visit slots only.
   - `POST /api/bookings` with `{ bookingType: 'home_visit', doctorId, availabilitySlotId, reason? }` → atomic slot lock (available + home_visit → booked), create assignment (`source='patient'`, `patient_profile_id`, status `pending`). If the slot was taken in between → "slot just taken", re-fetch.
   - `GET /api/bookings` (patient role) → my home-visit bookings + status.
   - Patient UI: search → pick doctor → pick date → pick home-visit slot → confirm.
4. **Doctor side (reuse)**
   - Accept/decline via existing `/api/assignments/[id]/status`.
   - Slot release on decline/cancel + expiry cron already exist.

### Phase 2 — Payments (future, undecided model)

- Patient pays → doctor, or patient → platform, or admin → doctor payout.
- Attach to the same `assignments` row; routing is a payment-layer decision, not a schema one.
- Fee source (doctor-set vs admin-set) TBD.

### Phase 3 — Real-time niceties (future)

- Travel time / ETA for home visits; slot duration modeling.
- Address privacy (show area/town at request, full address after acceptance).
- Cancellation windows / fees.
